# Лицензирование портативной сборки

Node-lock портативной сборки (флешка клиенту) на подписи Ed25519. Полная механика
и её честные ограничения описаны в `backend/app/core/license.py` — здесь только
что и в каком порядке делать руками.

## Разово, при первой настройке

```
python licensing/keygen.py
```

Создаёт `licensing/private_key.pem` (никогда не коммитить, не класть ни в одну
сборку — уже в `.gitignore`, и `build-portable.ps1` эту папку не копирует) и
печатает публичный ключ. Вставить его в `backend/app/core/license.py`,
в `PUBLIC_KEY_B64`. Готово — это делается один раз за всю жизнь проекта.
Повторный запуск `keygen.py` откажется перезаписать существующий ключ (иначе
все уже выданные `license.key` обесценятся).

## На каждого нового клиента

1. Клиенту переносят портативную сборку и запускают `start.bat` без
   `license.key`. Backend откажется стартовать и напечатает в окне «Fasad —
   сервер» отпечаток компьютера вида `XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX`.
2. Клиент присылает этот отпечаток.
3. Выпустить лицензию:
   ```
   python licensing/issue_license.py --fingerprint <отпечаток> --client "Название клиента"
   ```
   Необязательно: `--expires YYYY-MM-DD` для лицензии с истечением сроком.
   Результат — `licensing/licenses/<client>-license.key` (эта папка тоже в
   `.gitignore` — файлы с отпечатками клиентов туда не коммитятся).
4. Отправить `license.key` клиенту. Ему нужно положить файл рядом с
   `backend\.env` внутри его копии `fasad-portable` и перезапустить `start.bat`.

## Если потерян `private_key.pem`

Уже выданные `license.key` продолжат работать (подпись проверяется офлайн,
сервер для этого не нужен). Новые лицензии выпустить будет нельзя — придётся
`keygen.py` заново и заново вклеивать публичный ключ в `license.py`, но тогда
все ранее выданные лицензии перестанут проходить проверку (публичный ключ в
сборках у старых клиентов не совпадёт с новым приватным). Храните файл так же
бережно, как пароль от банка.
