# Холодная рассылка по фасадным производствам

Инструмент для продажи самой платформы: персональные письма руководителям
фасадных цехов, с журналом касаний и защитой от того, чтобы это превратилось в
спам.

Отправка идёт через уже настроенный почтовый канал (см.
[email-channel.md](email-channel.md)). Отдельных учётных данных нет: пароль
лежит зашифрованным в `ChannelAccount`, куда его положила админка.

## Почему это не «рассылка»

Ст. 18 38-ФЗ «О рекламе» запрещает рассылать рекламу по сетям электросвязи без
предварительного согласия адресата. Штраф по ч. 4.1 ст. 14.3 КоАП — от 300 тыс.
до 1 млн ₽ за доказанный факт.

Граница проходит не по объёму, а по содержанию: одинаковый шаблон, разосланный
по списку, — реклама неопределённому кругу лиц; письмо, написанное конкретной
компании про её производство, — обычная деловая переписка.

Поэтому `load_prospects` отказывается запускать кампанию, где:

- у двух компаний совпадает текст письма;
- в тексте нет ни названия компании, ни города (проверка по основам слов, чтобы
  падежи не считались обезличенностью);
- один и тот же адрес указан дважды;
- письмо короче 120 знаков — незаполненная заготовка.

`render_body` дополняет каждое письмо подписью с реквизитами и строкой отказа
«Ответьте „нет“ — больше не напишу», если её нет в тексте.

## Файлы

| Файл | Назначение |
| --- | --- |
| `backend/app/modules/messaging/outreach.py` | Логика: список, журнал, отбор партии, проверки |
| `backend/scripts/outreach.py` | CLI |
| `backend/scripts/outreach_prospects.json` | Компании и письма |
| `backend/scripts/outreach_state.json` | Журнал отправок, создаётся при первом запуске |

Журнал — обычный JSON: его можно открыть, править руками и класть в бэкап.
Отдельной таблицы и миграции кампания не заслуживает.

## Как пользоваться

Запускать из `backend/`. Подпись обязательна — задайте `OUTREACH_SIGNATURE` в
окружении или передайте `--signature-file`.

```powershell
# что в списке и что уже ушло
python scripts/outreach.py --list

# посмотреть письма, которые уйдут — ничего не отправляя
python scripts/outreach.py --limit 5

# отправить партию через канал с кодом email-main
python scripts/outreach.py --channel email-main --send --limit 5

# компания ответила — исключить из очереди
python scripts/outreach.py --replied vokrug

# попросили не писать
python scripts/outreach.py --opt-out zakaz@example.ru
```

Без `--send` скрипт ничего не отправляет и не меняет журнал.

### Ключи

| Ключ | По умолчанию | Смысл |
| --- | --- | --- |
| `--limit` | 10 | Писем в одной партии |
| `--daily-limit` | 25 | Потолок за сутки; выше начинается спам-репутация |
| `--pause` | 150 | Пауза между письмами, секунды, с разбросом ±40 % |
| `--channel` | — | Код почтового канала, нужен только с `--send` |

Журнал сохраняется после каждого письма: обрыв на середине партии не приведёт к
повторной отправке тем, кому уже написали.

## Список компаний

Формат записи:

```json
{
  "code": "vokrug",
  "company": "ВОКРУГ",
  "city": "Челябинск",
  "email": "fasad@vokrug.ru",
  "subject": "учёт номенклатуры на фасадах",
  "body": "Здравствуйте. Пишу на адрес с сайта…",
  "note": "Юрлицо не подтверждено — проверить перед договором."
}
```

`note` — для человека, в письмо не попадает: там держим то, что нужно помнить
перед разговором (выручка, размер штата, что именно не проверено).

В файле лежат только адреса, подтверждённые на странице контактов компании.
Компании без найденного адреса в список не попадают: холодное письмо на
выдуманный ящик уходит постороннему человеку и сжигает репутацию домена.

## Что стоит сделать до первой отправки

- Прогреть домен: 3–4 недели, начиная с 5–10 писем в день. Лучше отдельный
  домен, а не основной.
- Настроить SPF, DKIM и DMARC. Без них письма уходят в спам независимо от текста.
- Проверить отправку на `mail-tester.com`, цель — 9–10 из 10.
- Подать бесплатное уведомление оператора персональных данных в РКН.
- Держать `--daily-limit` в пределах 20–30.
