## Production workflow

В системе выделен отдельный контур исполнения заказа в цехе. Он не смешивается с коммерческими `order_statuses`.

Базовые сущности:

- `production_workflows`
- `workflow_stages`
- `work_centers`
- `order_stage_instances`
- `stage_assignments`
- `stage_evidence`

Что уже поддерживается:

- запуск workflow по заказу
- очередь активных этапов
- старт, блокировка и завершение этапа
- автосоздание следующего этапа
- перевод заказа в `ready` после финального этапа
- фотофиксация этапа

## Отчёт работника по деталям

Для production added traceability на уровне детали:

- `stage_part_reports`
- привязка к `order_stage_instance`
- привязка к `part`
- привязка к `worker`
- done / defect quantity
- фото и комментарий в отчёте

Это позволяет ответить на вопросы:

- какая именно деталь была закрыта
- на каком этапе это произошло
- какой работник отчитался
- сколько деталей выполнено и сколько ушло в брак

## Правила завершения этапа

Этап нельзя завершить, если:

- по заказу есть детали, но не все они закрыты отчётами на этом этапе
- для этапа требуется фото, а фото нет ни в stage evidence, ни в отчётах по деталям
- для этапа требуется комментарий, а комментарий не передан

Также действует защита от переполнения:

- нельзя отчитаться по детали количеством больше, чем требуется по заказу

## Workers UI

Во frontend добавлены страницы:

- `/production`
- `/production/queue`
- `/production/orders/[id]`
- `/production/stages/[id]`
- `/workers`
- `/workers/[id]`

Рабочий сценарий:

1. открыть stage
2. выбрать деталь
3. указать done/defect quantity
4. приложить фото
5. отправить отчёт
6. после закрытия всех деталей завершить stage

## Статистика

Dashboard теперь показывает:

- количество активных этапов
- количество этапов в работе
- количество блокировок
- число отчётов по деталям
- done quantity
- defect quantity
- топ работников
- отчёты по участкам

Все плитки и строки сводки кликабельные — «проваливаются» в тот список, из
которого посчитано число: плитки в `/orders`, `/leads`, `/reports`, `/stock`,
`/production`; строка статуса — в заказы этого статуса
(`/orders?status_code=…`); работник — в свою карточку (если он заведён в
справочнике, а не подписан только именем); участок и группа склада — в
`/production` и `/stock`.

Заказчик о прежней сводке: «вкладки не активные, чтобы провалиться
посмотреть» — число без перехода заставляло искать те же записи руками.
